# 测谎跟踪全量视频 Badcase 分析报告

日期：2026-09-11

## 1. 结论摘要

当前系统的首要瓶颈不是 YOLO 候选检测，而是检测之后的目标身份决策：系统通常已经检测到真实目标，也维护着真实目标附近的轨迹，ranker 甚至经常将其排在第一，但由于分差不足、连续投票、身份路径校验和当前目标粘性等条件叠加，不能及时从错误身份切回真实目标。

瓶颈按当前影响排序为：

1. **身份切换决策与 ranker 置信度校准。**
2. **身份可信度没有进入鼠标安全控制。**
3. **未捕获初始白色高亮时无法冷启动。**
4. **遮挡或检测波动后的轨迹关联、coast 与重捕获。**
5. **YOLO 候选定位误差。**

其中第一项是当前端到端准确率的主要限制。继续单独优化候选检测器或单帧/listwise Top-1，预计收益有限；下一轮应直接优化“是否应该从当前身份切换到 challenger”的闭环决策。

## 3. 分析方法

### 3.1 离线真值

录像中的绿色光标中心作为离线真值。光标仅用于评估：进入 tracker 前会被遮罩并修复，不会作为 YOLO、轨迹特征或 ranker 输入。

预测中心与绿色光标中心的距离不超过 `40px` 时记为正确。

### 3.2 Badcase 分类

逐帧错误被拆为以下类别：

- **无输出：** 有绿色光标真值，但 tracker 没有输出目标中心。
- **轻度误差：** `40px < error <= 60px`。
- **中度误差：** `60px < error <= 100px`。
- **严重误差：** `error > 100px`。
- **纯预测错误：** 当前 REAL 轨迹处于 `predicted_only`。
- **可见轨迹身份错误：** 当前 REAL 仍有检测更新，但跟踪的对象不是实际目标。

此外，对主要困难视频进行了第二次逐帧诊断，检查：

1. 真值附近是否仍有 YOLO detection。
2. 真值附近是否仍有 tracker 轨迹。
3. ranker top1 是否靠近真值。
4. top1-top2 margin 是否达到 `2.0`。
5. 正确候选是否进入连续投票状态。

最后对全部21段错误帧做了稀疏 YOLO 重检，以避免仅从 tracker 输出反推检测器能力。

## 6. 瓶颈一：身份切换决策与置信度校准

对录屏3、6、8、9、10、15、19、20、22、23这10个主要困难视频进行了逐帧重放，共得到1,115个错误帧。

| 诊断条件 | 错误帧数 | 占1,115帧 |
| --- | ---: | ---: |
| 真值60px内仍有 YOLO detection | 1,015 | 91.03% |
| 真值60px内仍有可见 track | 1,029 | 92.29% |
| ranker top1 位于真值60px内 | 922 | 82.69% |
| ranker top1 正确且 margin >= 2.0 | 332 | 29.78% |
| 正确目标进入 ranker 连续候选状态 | 146 | 13.09% |
| ranker top1 明确排错 | 193 | 17.31% |
| 当前 REAL 处于纯预测 | 219 | 19.64% |

典型失败链路是：

```text
真实目标仍被 YOLO 检出
  -> tracker 中存在真实目标附近轨迹
  -> ranker 很多时候已经把它排到第一
  -> top1-top2 分差没有达到 2.0，或路径条件不允许
  -> 连续候选 streak 被清零或无法累计到 5 票
  -> 当前错误身份继续保持
```

当前 ranker 切换需要同时满足：

- top1 不是当前目标；
- top1-top2 margin 至少为 `2.0`；
- challenger 当前可见且不是纯预测；
- challenger 连续可见至少5帧；
- motion reliability 至少为 `0.10`；
- challenger 没有正在离开画面；
- multi-hypothesis identity path 允许切换；
- 当前目标正常可见时累计5票；
- 当前目标丢失或纯预测时累计3票。

每一条保护条件单独看都合理，但叠加后会造成明显的恢复延迟。尤其当“当前目标是错的，但仍有稳定检测框”时，它仍被视为健康目标，需要更严格的5票切换。

旧19段 A/B 中，margin `0.5` 的准确率为68.04%，但产生128次身份切换；margin `2.0` 的准确率为67.54%，切换降到82次，并消除了录屏11、13的主要回归。这说明当前固定 margin 在“恢复速度”和“误切换”之间只能做全局折中，缺少随场景变化的置信度校准。

## 7. 瓶颈二：错误身份仍被判定为可操作

有输出的1,422个错误帧中，1,416帧仍被标记为 `actionable`，占99.58%。

当前 `actionable` 主要由位置轨迹是否为检测更新，以及 Kalman 位置不确定度决定：

```python
actionable = (
    not target.predicted_only
    or 4.0 * uncertainty <= max(8.0, float(radius))
)
```

这个条件回答的是“当前位置估计是否稳定”，不是“当前身份是否是真目标”。所以一条稳定但错误的 BG 轨迹会得到很高的位置置信度，并继续驱动鼠标。

这不仅影响离线准确率，也是当前线上风险最大的一环。建议将位置可信度和身份可信度拆开：

```text
mouse_actionable = position_confident AND identity_confident
```

身份可信度可由以下信号组合：

- 当前目标与 ranker top1 是否一致；
- top1-top2 margin 的校准概率；
- 当前目标是否符合整体背景运动；
- challenger 是否连续获得多种独立证据；
- 最近一次身份切换是否被后续帧验证；
- 当前目标是否处于异常 coast、外观突变或局部运动不一致状态。

## 8. 瓶颈三：无白色种子时不能冷启动

录屏5、7、12、17贡献了全部1,030个无输出帧。它们的共同特点是有效评估区间早于 tracker 观察到初始白色高亮：

| 视频 | 有效区间开始 | 首次白色高亮 | 结果 |
| --- | ---: | ---: | --- |
| 录屏5 | 0.00s | 7.00s | 前6.9秒无 REAL |
| 录屏7 | 4.37s | 9.93s | 整个有效区间无 REAL |
| 录屏12 | 0.00s | 10.30s | 前10.3秒无 REAL |
| 录屏17 | 0.00s | 9.58s | 前9.58秒无 REAL |

这些帧平均仍有约15个 YOLO 候选。全量错误帧稀疏重检中，104个无输出采样帧有93个在真值60px内存在候选，比例为89.42%。

当前逻辑只有观察到白色高亮后才设置 `white_seen`、建立 `target_id`，而后续角色分配也只在 `white_seen` 为真时执行。因此以下情况会失去恢复能力：

- 录像或程序从挑战中途开始；
- 面板确认过慢，错过初始白色帧；
- 初始高亮检测失败；
- 测谎过程中 tracker 被重置或程序重启。

这些样本不应全部算作正常线上流程中的检测失败，因为线上通常会从面板出现起连续运行；但它们揭示了一个明确的鲁棒性缺口。

## 9. 瓶颈四：遮挡后的关联和重捕获

纯预测状态解释了约22.22%的有输出错误，不是全局第一瓶颈，但对以下视频影响明显：

- 录屏6：69个错误预测帧；
- 录屏11：末段约1秒持续 coast；
- 录屏19：31个错误预测帧；
- 录屏22：31个错误预测帧；
- 录屏23：21个错误预测帧。

典型表现为：

1. REAL 短时漏检。
2. Kalman 继续外推旧轨迹。
3. 真实目标已经以新 track 身份重新出现。
4. 外观、路径或连续票数不足以立即完成 handoff。
5. 系统继续输出旧轨迹，或在恢复时关联到错误背景对象。

因此关联与重捕获仍需要优化，但其影响小于“可见但身份选错”。

## 11. 当前 Ranker 的泛化问题

当前43特征模型指标：

| 指标 | 结果 |
| --- | ---: |
| 固定验证集 Top-1 | 90.69% |
| LOVO Top-1 | 86.19% |
| LOVO Hard Top-1 | 77.94% |
| 原19段端到端40px准确率 | 67.54% |

模型的重要特征主要包括：

- `radius_norm`；
- `x_norm`、`y_norm`；
- `distance_to_centroid_norm`；
- orientation；
- `appearance_peer_z`；
- 历史速度和外观统计。

而旧版显式旋转、平移残差、刚性分数的重要性较低。这说明模型仍较依赖位置、尺寸和已有数据分布，没有完全学到“相对于整体运动不合理的对象才是真目标”。

录屏22没有出现在原19段训练集中，最终只有64.86%，也暴露了新视频泛化问题。

运动特征实验将 LOVO Top-1 提升到92.58%、Hard Top-1提升到88.53%，但端到端只有65.76%，仍低于当前模型的67.54%。这表明单帧或单 query 排序能力并不能直接转化为在线效果：一次切换会改变后续 track 历史，继续影响下一次 ranker 输入，形成闭环反馈。

## 12. 建议的优化优先级

### P0：建立独立的身份可信度和鼠标安全门

在 identity confidence 较低时暂停鼠标，而不是继续跟随一个位置稳定但身份不可信的目标。

目标是优先减少“错误且 actionable”的1,416帧。即使短期内不提高目标恢复率，也应先避免把明显不确定的身份输出给鼠标。

### P1：训练 switch-event 模型，而不是继续只训练 listwise ranker

训练样本应以实际切换事件为单位：

```text
输入：current track + challenger + peer constellation + 最近历史
标签：现在切换是否能降低未来 N 帧的真实误差
```

建议预测：

- `P(challenger is REAL)`；
- `P(switch improves next N frames)`；
- `P(current target is wrong)`。

决策应显式区分：

- 当前目标健康且证据一致；
- 当前目标可见但身份可疑；
- 当前目标纯预测；
- 当前目标已消失；
- 尚未获得任何白色种子。

### P2：将固定 margin 改成状态相关门槛

不建议直接全局降低 `2.0`，因为旧实验表明 margin `0.5` 会显著增加误切换。更合理的是动态门槛：

- 当前目标稳定且证据一致：保持高门槛。
- 当前目标与整体运动高度一致、疑似背景：降低门槛。
- 当前目标纯预测或长时间 lost：减少投票数并降低门槛。
- challenger 同时满足 ranker、光流异常和多 lag 旋转：降低门槛。
- 多个候选分数接近：暂停鼠标，不立即切换。

### P3：补充冷启动恢复

当连续一段时间有候选却从未看到白色种子时，允许进入保守冷启动模式：

1. 积累所有候选的相对运动历史。
2. 等待一个候选持续表现为整体运动异常值。
3. 只有多种证据一致时建立 provisional REAL。
4. 冷启动期间默认不移动鼠标。
5. 后续一旦再次观察到明确高亮，用高亮强制校正身份。

### P4：改善轨迹 handoff 与重捕获

- 将 appearance、局部光流、全局相似变换残差用于旧 REAL 与新 track 的二元重关联。
- 对纯预测 REAL 使用更激进的 challenger 恢复策略。
- 把“正确候选连续存在但当前目标持续错误”作为专门的训练场景。
- 避免错误 REAL 的长 coast 被当作高置信输出。

### P5：最后再优化检测框定位

可通过关键点/中心回归或更精确的 box-to-center 校准改善40–60px边界误差，但它不是当前主要瓶颈，应放在身份决策之后。

## 13. 下一轮实验建议

建议按以下顺序做消融：

1. **Safety-only：** 不改变身份切换，只增加 identity confidence；低置信度时禁止鼠标移动。
2. **State-aware margin：** 对可疑 current、predicted-only、lost 三种状态分别设置门槛和票数。
3. **Motion corroboration：** 保留当前43特征 ranker，仅用 optical flow + multi-lag rotation 作为切换佐证。
4. **Switch-event classifier：** 直接训练“切换是否改善未来误差”。
5. **Cold-start fallback：** 对没有白色种子的录像进行保守恢复。
6. **Joint replay tuning：** 用端到端回放结果选参数，而不是只按离线 Top-1 选模型。

评估时至少同时报告：

- Active-frame 40px准确率；
- Covered-frame 40px准确率；
- 无输出帧比例；
- 错误且 actionable 的帧数；
- 严重错误帧数；
- 身份切换次数；
- switch-event 改善/回归数量；
- 每段视频最差连续错误时长；
- 旧19段与新录屏22、23分别统计，防止只优化旧数据。

## 14. 最终判断

当前系统已经能够稳定检测出绝大多数候选，正式 ranker 也相较无 ranker 基线提升了端到端效果。但系统尚未解决最关键的在线问题：

> 当当前身份稳定但错误、正确候选同时存在时，如何有足够把握地及时切换；当把握不足时，又如何安全地暂停鼠标。

因此，下一阶段应从“哪个候选分数最高”转向“当前身份是否仍可信、现在切换是否会改善未来轨迹”的序列决策问题。
